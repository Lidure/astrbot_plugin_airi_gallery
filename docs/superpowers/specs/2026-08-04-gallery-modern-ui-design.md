# Gallery 现代化桌面 UI 设计

日期：2026-08-04

## 目标

在不改变图库、分类昵称和后端 API 行为的前提下，提升 `pages/gallery` 在 AstrBot WebUI 桌面端中的视觉层级、品牌感和操作效率，并恢复分类昵称页面底部便于随时保存的悬浮操作栏。

本次属于 v2.11.0 的界面完善，不增加版本号。

## 视觉方向

采用“清爽桃粉管理台”风格：

- 浅灰中性页面背景和白色工作表面，避免整页被单一粉色占满。
- 桃粉色仅用于品牌、当前标签和主要操作；绿色用于保存成功及保存按钮；红色用于删除和错误。
- 使用现有 `logo.png` 的页面本地副本作为首屏品牌标识，替代字母方块。
- 使用清晰的边框、阴影和留白建立层级，不使用渐变、装饰光斑或大面积营销式视觉。
- 卡片和控件圆角不超过 8px，字体保持紧凑、易扫描。

## 页面框架

页面最大内容宽度从 920px 调整到适合桌面管理的约 1040px。顶部标题区包含 48px 插件 Logo、插件名称和简短副标题；标题区下方为“图库管理 / 分类昵称”分段控件。

分段控件与内容区对齐，占用稳定宽度。当前标签使用白色表面、桃粉文字和细阴影，非当前标签保持中性色。标签切换逻辑和可访问属性不变。

## 图库管理视图

上传卡片保留现有字段和拖放逻辑，但调整为更清楚的两段式工作区：

- 顶部为标题、用途说明和分类选择。
- 下方为大面积拖放区域、文件预览及上传按钮。

图库卡片将分类标签、每页数量和标题工具区组织在同一视觉层级。分类标签使用紧凑按钮样式；图片网格加强图片本身的展示，编号角标降低视觉噪声，删除按钮只在悬停或键盘聚焦时显示。

分页栏保持位于图片列表底部，按钮、页码选择和状态样式统一。

## 分类昵称视图

新增昵称表单保持单行桌面布局。昵称列表使用更清楚的表头、行分隔、悬停反馈和输入聚焦状态。删除按钮保持红色次要危险操作，不与保存按钮竞争视觉权重。

昵称列表卡片底部恢复悬浮操作栏：

- `.alias-actions` 使用 `position: sticky` 和 `bottom: 12px`。
- 操作栏具有独立白色背景、上边框和向上阴影，在滚动昵称表格时保持可见。
- 左侧状态持续显示“有未保存的修改”或“所有修改已保存”。
- 右侧保留“重新加载”和绿色“保存更改”。
- 保存按钮禁用时仍保持稳定尺寸，避免布局跳动。
- 内容区增加足够底部留白，悬浮栏不得遮挡最后一行昵称。

状态文本由现有 `setAliasesDirty` 统一更新：未保存时显示警示状态，保存或重新加载成功后显示已保存状态。加载失败时保留当前编辑内容和现有错误提示行为。

## 动效与交互

仅使用 120-180ms 的颜色、边框、阴影和轻微位移动效。按钮点击、标签切换、图片悬停和输入聚焦应有明确反馈。继续支持 `prefers-reduced-motion`，关闭非必要动画。

不引入前端框架、图标库或新的运行依赖。功能逻辑、API 名称、配置格式和 DOM 主接口保持不变。

## 桌面范围

本次按用户要求只设计和验收桌面网页，目标视口为 1280x800 和 1440x900。现有窄屏响应式规则保留为基础回退，但不新增手机端布局、控件重排或手机截图验收。

## 文件变更

- `pages/gallery/logo.png`：从仓库根目录的现有 Logo 复制，避免插件页面静态资源跨目录加载失败。
- `pages/gallery/index.html`：使用 `./logo.png` 替换字母标识，补充桌面工作区所需的语义类名。
- `pages/gallery/style.css`：重做桌面视觉层级、控件状态和悬浮保存栏。
- `pages/gallery/app.js`：补充“所有修改已保存”状态文案，不改 API 和核心数据流。
- `tests/test_repository_contract.py`：增加 Logo、悬浮保存栏和保存状态接线契约。

## 测试与验收

自动测试验证：

- 页面引用 `./logo.png`，且页面本地 Logo 文件存在。
- 昵称操作栏继续包含保存、重新加载和状态区域。
- CSS 明确包含 `position: sticky` 与稳定底部偏移。
- `setAliasesDirty` 同时覆盖未保存和已保存状态文案。
- Python 3.10 和 3.12 的全部现有测试继续通过。

桌面视觉验收检查：

- 1280x800 和 1440x900 下无重叠、裁切或文本溢出。
- 两个主视图的标题、工具区和内容层级一致。
- 昵称列表滚动时保存栏保持可见，且不遮挡最后一行。
- Logo、图片、分类标签、分页和所有按钮正常显示。

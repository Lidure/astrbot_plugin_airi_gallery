# Airi Gallery 新手配置自检设计

## 目标

为 Airi Gallery 增加一个面向新手用户的只读诊断功能。用户可以通过 `/画廊检查` 快速判断本地图库、插件配置、权限保护、Git 远程同步、云端入口和插件版本是否正常，并获得具体的中文修复建议。

插件启动时复用同一套诊断逻辑，但只把警告和错误写入 AstrBot 日志，不向任何聊天主动发送消息，也不阻塞插件初始化。

## 非目标

- 不自动修改配置。
- 不创建、删除、移动或重排图库文件。
- 不重建哈希索引。
- 不通过上传、提交或删除测试文件验证远程写权限。
- 不自动下载或安装插件更新。
- 不在本阶段提供 Web 诊断页面。
- 不借此功能对 `main.py` 做无关的大规模重构。

## 用户入口

### 手动诊断

新增管理命令：

```text
/画廊检查
```

命令沿用现有管理命令的权限规则：

- `use_permission=false` 时，保持现有兼容行为，所有用户都可执行。
- `use_permission=true` 时，仅 AstrBot 管理员、`admins` 或 `whitelist` 中的用户可执行。
- 未授权时复用现有拒绝提示，不发起任何网络请求。

诊断报告不得显示 Token、上传密钥、认证请求头或带认证信息的 URL。仓库名称、分支和普通公开 URL 可以显示，但输出应以问题和修复动作优先，不重复打印完整配置。

### 启动诊断

插件初始化完成后启动后台诊断任务：

- 不等待诊断完成，不延迟插件可用时间。
- 只记录警告和错误；全部正常时记录一条简短汇总。
- 不向群聊或私聊发送消息。
- 插件终止时取消仍在运行的启动诊断任务。
- 启动诊断中的异常只能写入日志，不得导致插件初始化失败。

## 架构

新增独立模块 `gallery_diagnostics.py`。该模块负责诊断数据模型、纯配置检查、结果汇总、脱敏和报告格式化。`main.py` 负责提供运行时依赖、注册命令、调度网络检查以及管理启动任务。

### `DiagnosticItem`

单项诊断结果至少包含：

- `code`：稳定、可测试的检查标识。
- `level`：`ok`、`warning` 或 `error`。
- `title`：面向用户的中文检查名称。
- `message`：检查结果，不包含敏感值。
- `suggestion`：可选的中文修复建议。

### `DiagnosticReport`

诊断报告负责：

- 保存所有 `DiagnosticItem`。
- 统计正常、警告和错误数量。
- 生成简洁聊天报告。
- 生成适合 AstrBot 日志的摘要和问题行。
- 在全部正常时折叠普通项目，只显示汇总和关键图库统计。
- 在存在问题时只展开警告、错误和更新提示，避免长消息刷屏。

### 检查边界

`gallery_diagnostics.py` 中的本地检查尽量设计为纯函数，通过明确参数接收路径、配置和版本。远程访问由 `main.py` 复用现有 Git 请求能力，返回不含凭据的结构化结果，再交给诊断模块转换为 `DiagnosticItem`。

该边界避免维护第二套 Git 认证逻辑，也使配置、脱敏、版本比较和报告生成能够在没有 AstrBot 运行环境时进行单元测试。

## 检查内容

### 基础环境

- 图库根目录是否存在且为目录。
- 图库目录是否可读、可写。
- 可识别的分类数量和图片数量。
- `hash_index.json` 不存在时记为普通状态，因为插件支持按需重建。
- `hash_index.json` 存在但无法读取、无法解析或结构无效时记为警告，并建议备份后删除缓存让插件按需重建。

写权限检查不得为了测试而创建临时文件。使用系统提供的访问能力判断；若平台无法可靠确认，则显示警告而不是宣称可写。

### 浏览配置

检查并报告：

- `view_command_mode` 是否为 `no_prefix` 或 `prefix`。
- `view_multiple_mode` 是否为 `single` 或 `forward`。
- `view_multiple_max` 是否在插件支持范围内。
- `view_all_collage_scale` 是否在插件支持范围内。
- 其他数值配置是否可转换且落在实现支持的范围内。

插件运行时已有回退值的非法配置记为警告，并明确显示将采用的安全回退行为；不会自动写回配置。

### 权限安全

- `use_permission=false` 时记为警告，说明共享群组建议启用权限控制。
- `use_permission=true` 且 `admins`、`whitelist` 都为空时记为警告，但 AstrBot 平台管理员仍可能通过运行时管理员标识获准。
- 列表类型错误或包含空条目时记为警告并给出格式提示。
- 报告只显示条目数量，不显示用户标识内容。

### 云端入口

- `cloud_gallery_url` 为空时记为普通提示，不计入警告或错误。
- 非空时必须是可规范化的 `http` 或 `https` URL。
- URL 中含用户名、密码、查询密钥或片段时记为警告，报告仅显示脱敏后的主机信息。
- 本阶段不主动请求该页面，避免把外部站点暂时不可用误判为插件故障。

### Git 远程同步

`git_sync_enabled=false` 时，将 Git 检查标记为跳过，不视为异常，也不进行远程请求。

启用 Git 同步后依次检查：

1. `git_platform` 是否为插件支持的 `github` 或 `gitee`。
2. owner、repository、branch 和 token 是否齐全。
3. 配置不完整时生成明确错误，并停止后续 Git 网络检查。
4. 复用现有认证和请求逻辑，只读查询仓库与目标分支。
5. 区分认证失败、仓库不存在、分支不存在、限流、超时和一般网络错误。
6. 平台响应明确包含仓库写权限时显示正常。
7. 只能证明读取权限或平台未返回可靠权限字段时显示“写权限未能确认”，不得显示为已具有写权限。

整个检查不上传 Blob、不创建 Commit、不更新 Ref，也不删除远程文件。

### 版本更新

- 当前版本读取自插件自身的 `metadata.yaml` 或初始化时已知的版本常量。
- 最新版本从插件元数据仓库的固定原始文件地址读取，不抓取 HTML 页面。
- 使用语义化数字比较 `vMAJOR.MINOR.PATCH`，前导 `v` 可选。
- 远程版本高于当前版本时生成更新提示，包含当前版本、最新版本和仓库更新入口。
- 当前版本相同或更高时记为正常。
- 远程版本格式异常、请求超时、限流或网络失败时记为警告，不影响其他检查。
- 更新结果在进程内短期缓存 10 分钟，连续运行命令时不重复消耗 API 请求。
- 只提示更新，不运行 `git pull`，也不覆盖用户本地修改。

## 数据流

### 手动命令

1. `main.py` 完成权限判断。
2. 收集当前配置、图库路径、统计信息和版本。
3. 在工作线程中运行可能阻塞的文件系统及网络检查。
4. 各检查返回结构化结果；单项异常在边界处转换为诊断项目。
5. `DiagnosticReport` 生成聊天文本。
6. 命令发送一条文本报告，不生成图片海报。

### 启动检查

1. `initialize()` 完成插件基础初始化。
2. 创建独立后台任务运行同一诊断入口。
3. 任务完成后把摘要及问题写入日志。
4. `terminate()` 取消并等待尚未结束的任务，取消异常不向外传播。

## 输出约定

报告标题为 `Airi 画廊检查`，首行汇总正常、警告和错误数量。级别使用明确文本标记，不依赖颜色或复杂图片：

```text
Airi 画廊检查

结果：8 项正常，2 项警告，1 项错误
图库：12 个分类，438 张图片

[错误] 远程分支
未找到分支 main
建议：检查 git_branch 配置

[警告] 权限保护
当前未启用管理命令权限控制
建议：共享群组建议启用 use_permission

[更新] 发现 v2.10.0
当前版本：v2.9.1
```

“发现更新”作为提示展示，不增加错误数量。若内部数据模型需要独立级别，可以使用 `update` 展示类型，但汇总时归入普通提示。

报告必须限制长度。多个同类配置错误应合并，异常原文需要清理 URL、请求头和凭据后才能进入日志。不得直接输出 `repr(config)`、完整 HTTP 异常对象或完整响应正文。

## 错误处理与性能

- 每个检查单元独立捕获预期异常，一个检查失败不终止整个报告。
- 未知异常转换为不含内部敏感上下文的错误项目，并在调试日志记录经过脱敏的异常类型。
- 网络请求使用插件现有超时策略；诊断入口不得无限等待。
- 手动诊断运行期间不持有图库写锁或 Git 推送锁。
- 启动诊断与定时同步可并发读取远程状态，但不会修改共享数据。
- 版本检查缓存只存版本号、检查时间和非敏感错误类型。

## 帮助与文档

- 在画廊帮助文字和 README 管理命令表中加入 `/画廊检查`。
- README 增加“新手排障”小节，说明检查范围、只读保证和常见结果。
- `_conf_schema.json` 的相关提示与诊断规则保持一致，但本功能不新增必须配置项。
- 本功能完成后按发布范围更新版本号和更新日志；具体版本在实施计划中统一确定，避免设计阶段提前产生不一致版本。

## 测试策略

新增无需 AstrBot 环境即可运行的单元测试，覆盖：

- 正常配置、缺失配置、错误类型和越界数值。
- 权限关闭、授权列表为空、列表格式错误及报告不泄露用户标识。
- Git 未启用、必要字段缺失、连接失败、认证失败、仓库或分支不存在。
- 平台明确返回写权限、只确认读取权限和权限字段缺失。
- 当前版本、发现新版、远程版本格式异常、超时和缓存命中。
- Token、上传密钥、认证 URL、HTTP 请求头和异常正文不会进入聊天报告或日志。
- 单项检查异常不会阻止其他项目生成结果。
- 启动检查不发送聊天消息，不阻塞初始化，并可在终止时取消。
- 仓库契约测试覆盖命令注册、README 帮助、配置 JSON 和版本一致性。

网络测试使用假响应或注入的请求函数，不访问真实 GitHub/Gitee。最终验证继续运行完整 `pytest`、Python 语法编译、JSON/YAML 解析及 `git diff --check`。

## 验收标准

- 新手执行一次 `/画廊检查` 就能看到插件是否可用以及每个异常的具体修复方向。
- Git 未启用的本地用户不会因缺少远程配置看到错误。
- Git 已启用但配置或连接有问题时，报告能区分主要失败原因。
- 任何报告和启动日志都不包含配置中的 Token、上传密钥或认证信息。
- 诊断过程不改变本地文件、插件配置和远程仓库状态。
- 启动诊断失败不会阻止插件加载。
- 更新检查只提示，不自动更新。
